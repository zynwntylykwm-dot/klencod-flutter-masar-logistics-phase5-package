# دليل تشغيل المساعد الذكي (المرحلة 5)

> هذا الدليل عملي: كيف يتحوّل المساعد من «محرّك قواعد» إلى **نموذج ذكاء اصطناعي حقيقي** بمفتاح واحد،
> وكيف تُدار إجاباته وأسئلته الشائعة من لوحة الإدارة.

---

## 1) الحالة الافتراضية — بلا أي مفتاح

عند تشغيل الخادم بلا مفاتيح، يعمل المساعد بـ **محرّك قواعد مُسنَد إلى بياناتك الحقيقية**:

| ما يستطيع فعله | من أين يقرأ |
|---|---|
| تتبّع شحنة برقمها (الحالة، الموقع، التقدّم، المتبقي) | جدول `shipments` |
| حساب تكلفة الشحن (رسم + كيلو + م³ + خصم + حد أدنى) | محرّك التسعير `pricing_rules` |
| عرض رصيد المحفظة والمحجوز | `wallet_accounts` |
| عدد المزادات المفتوحة ومزايدات المستخدم | `auctions` / `bids` |
| الإجابة عن الأسئلة الشائعة المعتمدة | `assistant_faq` |
| تحويل لموظف بشري عند الشكوى | توجيه لصفحة الدعم |

وفي هذه الحالة تُظهر الواجهة للمستخدم بصراحة:
> «محرّك قواعد مُسنَد إلى بياناتك (بلا مفتاح AI)»

**وهذا ليس ذكاءً اصطناعيًا، ولا نقدّمه على أنه كذلك.**

---

## 2) تفعيل نموذج حقيقي — اختر مزوّدًا واحدًا

أضف المتغيّرات في بيئة الخادم (أو `deploy/.env` مع docker-compose) ثم أعد التشغيل:

### أ) OpenAI
```bash
export AI_API_KEY=sk-...
export AI_MODEL=gpt-4o-mini
node server/server.js
```

### ب) أي خدمة متوافقة مع OpenAI (OpenRouter / LocalAI / vLLM / LiteLLM)
```bash
export AI_API_KEY=sk-or-...
export AI_BASE_URL=https://openrouter.ai/api/v1
export AI_MODEL=openai/gpt-4o-mini
```

### ج) Anthropic Claude
```bash
export ANTHROPIC_API_KEY=sk-ant-...
export ANTHROPIC_MODEL=claude-3-5-sonnet-latest
```

### د) Google Gemini
```bash
export GEMINI_API_KEY=...
export GEMINI_MODEL=gemini-1.5-flash
```

### هـ) نموذج محلي بلا مفاتيح ولا إنترنت (Ollama)
```bash
ollama pull llama3.1
export OLLAMA_HOST=http://127.0.0.1:11434
export OLLAMA_MODEL=llama3.1
```

### مع Docker
```bash
cp deploy/.env.example deploy/.env
# عدّل AI_API_KEY في deploy/.env
docker compose -f deploy/docker-compose.yml up -d --build
```

بعد التفعيل يصبح في الواجهة: `متصل بنموذج OpenAI`، وفي اللوحة: `🤖 يعمل بنموذج …`.

## 3) ما يرسله المساعد إلى المزوّد (الخصوصية)

يُرسل **فقط**: تعليمات النظام + ملخّص محدود عن المستخدم:
اسمه، رتبته، عدد شحناته، آخر 8 شحنات (رقم/حالة/موقع/متبقٍ)، رصيده، عدد المزادات.

**لا يُرسل إطلاقًا**: كلمة المرور، تجزئتها، الـ salt، رموز الجلسات، بيانات عملاء آخرين.
وهذا مُختبَر آليًا في `scripts/test-phase5.js` (اختبار «لا تُرسَل كلمة المرور إلى المزوّد»).

## 4) الإدارة من اللوحة

**الإعدادات ← 🛡️ الإدارة والإشعارات ← فتح لوحة الإدارة ← المساعد الذكي**

- **حالة المساعد**: هل النموذج مفعّل؟ وأي مزوّد؟ ولماذا لا (سبب صريح).
- **مزوّدو الذكاء الاصطناعي**: كل مزوّد بحالته (`جاهز` / `غير مهيّأ`) واسم متغيّر البيئة المطلوب.
- **إعدادات المساعد** (للمدير العام):
  - المزوّد المفضّل: تلقائي / مزوّد محدد / **محرّك القواعد فقط** (لتعطيل النموذج).
  - الحد اليومي لكل مستخدم (1–1000).
  - الحرارة (0–1)، أقصى رموز للرد (64–4096).
  - تعليمات إضافية تُضاف إلى تعليمات النظام (مثال: «اذكر أن الشحن الجوي أسرع»).
  - مفتاح تشغيل/إيقاف المساعد كاملًا (الإيقاف يرجّع 503 فورًا).
- **جرّب المساعد الآن**: اختبار فوري مع بيان المصدر وزمن الرد وسبب أي تراجع.
- **أكثر الأسئلة**: تجميع الأسئلة الحقيقية لتحسين قاعدة المعرفة.
- **قاعدة الأسئلة الشائعة**: إضافة/تعديل/تعطيل/حذف (الحذف للمدير العام فقط).
- **آخر المحادثات**: قراءة أي محادثة كاملة للإدارة (مع بصمة المصدر لكل رد).

كل هذه الإجراءات تُسجَّل في **سجل التدقيق** (`assistant_settings_update`, `assistant_faq_create`, …).

## 5) نقاط النهاية (API)

```
GET    /api/assistant/public                    ← معاينة عامة بلا بيانات (قبل الدخول)
GET    /api/assistant/status                    ← الحالة الكاملة لمستخدم مسجّل
POST   /api/assistant/chat                      ← { message, conversation_id }
GET    /api/assistant/conversations             ← محادثات المستخدم
GET    /api/assistant/conversations/:id         ← رسالة برسالة + المصادر
POST   /api/assistant/feedback                  ← { message_id, value: up|down|null }

GET    /api/admin/assistant/status              ← branch_manager+
PATCH  /api/admin/assistant/settings            ← super_admin
GET    /api/admin/assistant/stats?days=30       ← branch_manager+
GET    /api/admin/assistant/conversations       ← + /:id
POST   /api/admin/assistant/test                ← اختبار مسجَّل بقناة admin_test
GET    /api/admin/assistant/faq                 ← + POST / PATCH / DELETE
```

كل رد يُرجع: `engine` (`model` أو `rules`)، `provider`، `model`، `grounded`، `sources[]`،
`latency_ms`، `usage`، `degraded`، `reason`، `conversation_id`، `message_id`، `quota`.

---

## 6) السلوك عند الفشل — بصدق

| الحالة | ما يحدث |
|---|---|
| لا مفاتيح | `engine=rules` + `reason` يشرح السبب للمستخدم |
| مفتاح خاطئ / شبكة مقطوعة | `engine=rules` + `degraded=true` + `reason` فيه رسالة المزوّد، والرد من القواعد |
| المزوّد يردّ 500 | نفس السلوك أعلاه — لا تعليق للواجهة ولا تلفيق نجاح |
| تجاوز الحد اليومي | `429` مع `quota {limit, used}` |
| المساعد معطّل من الإدارة | `503` |
| رسالة أطول من 2000 حرف | `400` |

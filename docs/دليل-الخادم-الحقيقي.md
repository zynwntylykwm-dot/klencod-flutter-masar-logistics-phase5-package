# دليل تشغيل الخادم الحقيقي — المسار العالمي اللوجستي (المرحلة 3)

هذا الدليل ينقلك من «تشغيل على جهازك» إلى **خادم حقيقي على الإنترنت** يعمل 24/7 باسم نطاق وشهادة HTTPS،
مع نسخ احتياطي يومي، وإشعارات تعمل على أندرويد وآيفون.

---

## 0) ما الذي تحتاجه

| البند | التكلفة التقريبية | ملاحظات |
|---|---|---|
| سيرفر VPS (2 vCPU / 2GB RAM / 40GB SSD) | 5–12 دولارًا شهريًا | أي مزوّد: Hetzner, DigitalOcean, Contabo, AWS Lightsail… |
| نطاق (Domain) | 8–15 دولارًا سنويًا | مثال: `api.masar-logistics.com` |
| Docker (اختياري) | مجاني | يبسّط التشغيل والتحديث |

الخادم **لا يحتاج أي حزم npm** — Node 20 فقط. الذاكرة الفعلية المستخدمة ~70–120MB.

## 1) تجهيز السيرفر (Ubuntu 22.04/24.04)

```bash
ssh root@YOUR_SERVER_IP

# تحديث النظام
apt update && apt upgrade -y

# جدار الحماية
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable

# تثبيت Node 20 (بدون Docker)
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs git

# أو تثبيت Docker (للطريقة الثانية)
curl -fsSL https://get.docker.com | sh
```

### توجيه النطاق
في لوحة DNS لمزوّد النطاق أضف سجلًا:

| النوع | الاسم | القيمة |
|---|---|---|
| A | `api` | عنوان IP للسيرفر |

انتظر 5–30 دقيقة حتى ينتشر السجل (`dig api.example.com`).

## 2) الطريقة الأولى: Docker + HTTPS تلقائي (مستحسن)

```bash
# 1) انسخ المشروع إلى السيرفر
git clone <repo> /opt/masar       # أو ارفعه بـ scp
cd /opt/masar

# 2) إعداداتك
cp deploy/.env.example deploy/.env
nano deploy/.env        # DOMAIN و ADMIN_PASSWORD على الأقل

# 3) تشغيل
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d

# 4) تحقق
docker compose -f deploy/docker-compose.yml ps
curl https://api.example.com/api/health
```

Caddy يحصل على شهادة Let's Encrypt تلقائيًا ويجدّدها، ويضبط ترويسات الأمان ويمرّر SSE بدون تخزين مؤقت.
خدمة `backup` تُنشئ نسخة مضغوطة يوميًا في `deploy/backups/` وتحتفظ 14 يومًا.

**التحديث لاحقًا:**
```bash
git pull
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
```

## 3) الطريقة الثانية: systemd + nginx (بدون Docker)

```bash
# مستخدم مخصص وبياناته
useradd -r -s /bin/false masar
mkdir -p /opt/masar /var/lib/masar /etc/masar
chown -R masar:masar /var/lib/masar

# نسخ الكود
rsync -a ./ /opt/masar/           # من جهازك أو git clone
chown -R masar:masar /opt/masar

# متغيّرات البيئة
cat > /etc/masar/masar.env <<'ENV'
PORT=8080
HOST=127.0.0.1
DATA_DIR=/var/lib/masar
ADMIN_PASSWORD=كلمة-مرور-قوية
LOGIN_RATE_LIMIT=40
VAPID_SUBJECT=mailto:you@example.com
ENV
chmod 600 /etc/masar/masar.env

# الخدمة
cp deploy/masar.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now masar
systemctl status masar --no-pager

# nginx + HTTPS
apt install -y nginx certbot python3-certbot-nginx
cp deploy/nginx.conf /etc/nginx/sites-available/masar
sed -i 's/api.example.com/YOUR_DOMAIN/' /etc/nginx/sites-available/masar
ln -sf /etc/nginx/sites-available/masar /etc/nginx/sites-enabled/masar
nginx -t && systemctl reload nginx
certbot --nginx -d YOUR_DOMAIN
```

**نسخ احتياطي يومي:**
```bash
crontab -e
# أضف:
15 3 * * * /opt/masar/deploy/backup.sh >> /var/log/masar-backup.log 2>&1
```

**سجلات:**
```bash
journalctl -u masar -f          # سجل الخادم الحيّ
/opt/masar/deploy/healthcheck.sh https://YOUR_DOMAIN/api/health
```

## 4) أول دخول بعد النشر

1. افتح `https://YOUR_DOMAIN` في المتصفح.
2. سجّل الدخول: `admin` + كلمة المرور التي وضعتها في `ADMIN_PASSWORD`
   (إن لم تضعها، ستجدها في `/var/lib/masar/BOOTSTRAP_ADMIN.txt` ثم احذف الملف).
3. **غيّر كلمة المرور فورًا** من: الإعدادات ← الأمان.
4. الإعدادات ← **🛡️ الإدارة والإشعارات** ← «فتح لوحة الإدارة».
5. اضغط **🔔 تفعيل الإشعارات على هذا الجهاز** لاختبار Web Push، ثم «إرسال إشعار تجريبي».

## 5) تشغيل الإشعارات على الأجهزة

### أ) Web Push — يعمل فورًا (أندرويد + آيفون)
- **أندرويد (Chrome):** افتح الموقع ← القائمة ← «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية» ← افتح التطبيق ← لوحة الإدارة ← تفعيل الإشعارات.
- **آيفون (Safari):** يجب أولًا «مشاركة ← إضافة إلى الشاشة الرئيسية» (iOS 16.4+ فقط)، ثم افتحه من الأيقونة واسمح بالإشعارات.
- المفاتيح (VAPID) تُولَّد تلقائيًا على الخادم وتُحفظ في `/var/lib/masar/vapid.json`. **لا تحذفها**، وإلا تعطّلت كل الاشتراكات.
- بديل: ضع `VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` في البيئة (مفيد عند تشغيل أكثر من نسخة خلف موازن تحميل).

### ب) FCM — إشعارات تطبيق أندرويد الأصلي (APK)
1. أنشئ مشروعًا في [Firebase Console](https://console.firebase.google.com) وأضف تطبيق أندرويد بحزمة `com.almasar.logistics`.
2. Project settings ← Service accounts ← **Generate new private key** → نزّل ملف JSON.
3. ضع محتوى الملف كاملًا في المتغير `FCM_SERVICE_ACCOUNT` (سطر واحد) وأعد تشغيل الخادم.
4. حالة القناة تظهر في لوحة الإدارة: «جاهز».
5. داخل التطبيق يلزم استدعاء Firebase SDK للحصول على `FCM token` ثم إرساله إلى `POST /api/push/device`
   بالشكل: `{"token":"...","platform":"android","app":"client"}`.
   > ⚠️ **لم يُضمَّن Firebase SDK داخل الـAPK الحالي** (لا مفاتيح مشروعك). وبدونه تعمل الإشعارات داخل التطبيق أثناء فتحه (SSE) وتصل إشعارات Web Push إن ثبّت النسخة كـPWA.

### ج) APNs — إشعارات تطبيق آيفون الأصلي
1. في [Apple Developer](https://developer.apple.com) ← Certificates, Identifiers & Profiles ← Keys ← أنشئ مفتاحًا مع تفعيل **Apple Push Notifications service (APNs)** → نزّل `.p8` (مرة واحدة فقط).
2. ضع في البيئة: `APNS_KEY_P8=/path/AuthKey_XXXX.p8` + `APNS_KEY_ID=XXXX` + `APNS_TEAM_ID=YYYY` + `APNS_BUNDLE_ID=com.almasar.logistics`.
3. أعد تشغيل الخادم — تصبح القناة «جاهزة» في لوحة الإدارة.
4. التطبيق يرسل رمز الجهاز إلى `POST /api/push/device` بـ`platform: "ios"`.

## 6) قائمة تحقّق أمنية قبل الإنتاج

- [ ] `ADMIN_PASSWORD` قوية (16 حرفًا+) وليست الافتراضية.
- [ ] HTTPS مفعّل (Caddy/certbot) والوصول عبر HTTP يُحوَّل تلقائيًا.
- [ ] `DEMO_MODE=false` إن لم تعد تحتاج الشحن التجريبي للمحفظة.
- [ ] `LOGIN_RATE_LIMIT` مضبوط (40 افتراضيًا لكل IP/15 دقيقة).
- [ ] نسخة احتياطية تُنشأ يوميًا وتُنسخ خارج السيرفر (S3/جهاز آخر).
- [ ] `/var/lib/masar/BOOTSTRAP_ADMIN.txt` محذوف بعد تغيير كلمة المرور.
- [ ] `data/vapid.json` محفوظ في مكان آمن (فقدانه يُبطل اشتراكات الدفع).
- [ ] مراقبة: UptimeRobot على `https://YOUR_DOMAIN/api/health` كل 5 دقائق.
- [ ] تحديث Node دوريًا (`apt upgrade`).

## 7) الصيانة والمراقبة

| المهمة | الأمر |
|---|---|
| حالة الخادم | لوحة الإدارة ← تبويب «الخادم» (إحصاءات حقيقية: مستخدمون، زوار، ذاكرة، تشغيل) |
| نسخة احتياطية يدوية | لوحة الإدارة ← «⬇️ نسخة احتياطية» (ملف JSON بكل المجموعات) |
| استعادة | أوقف الخادم، فك ضغط النسخة إلى `DATA_DIR`، ثم شغّله |
| سجل التدقيق | لوحة الإدارة ← تبويب «السجل» (كل عملية إدارية مع المنفّذ والوقت) |
| سجل الأخطاء | `journalctl -u masar` أو `docker logs masar-api` |

### التوسّع لاحقًا
- تخزين JSON على القرص يكفي حتى عشرات آلاف المستخدمين والزيارات. للانتقال إلى **PostgreSQL**
  تُستبدل `server/lib/store.js` فقط بنفس الواجهة (`insert/update/all/findOne/persist`) دون لمس بقية الكود.
- لتشغيل أكثر من نسخة: ضع موازن تحميل (nginx) + اجعل `DATA_DIR` على تخزين مشترك، وثبّت مفاتيح VAPID في البيئة.

## 8) ما هو حقيقي وما يحتاج مفاتيحك (بصراحة)

| البند | الحالة |
|---|---|
| خادم HTTP + REST + SSE + قاعدة بيانات على القرص | ✅ حقيقي ويعمل الآن |
| مصادقة وصلاحيات وسجل تدقيق | ✅ حقيقي |
| لوحة إدارة (مستخدمون/عملاء/زوار/إشعارات/سجل/حالة خادم) | ✅ حقيقية وتُدار من الخادم |
| Web Push (VAPID + تشفير RFC 8291) | ✅ حقيقي ومُختبر (فك تشفير تحقّقي في الاختبارات) |
| إشعارات داخل التطبيق لحظية | ✅ حقيقية |
| FCM / APNs | ⚙️ الكود جاهز وخادم الإرسال مبني بالكامل، **لكن يحتاج مفاتيح حسابك** — قبل ذلك تظهر «غير مهيّأ» ولا يدّعي الإرسال |
| HTTPS تلقائي | ✅ عبر Caddy (يحتاج نطاقك) |
| بوابة دفع | ❌ غير موصولة |
| تتبع شركات الشحن | ❌ يحتاج مفاتيح API من الشركات |
